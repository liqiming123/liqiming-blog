带货团队有个反复出现的场景：刷到一条爆款带货视频，想用自己的达人、自己的商品重拍一条「同款」。传统做法是编导逐帧拆解、写脚本、约达人、进棚拍、后期上字幕——一条视频一周起步。达人引流就是把这个流程模型化：**对标视频丢进去，AI 拆出分镜脚本和口播，换成你的达人人设图和商品图重新生成，字幕、成本、素材全部在浏览器里闭环**。

![爆款复刻工作台](/uploads/2026-11/daren-faceswap.webp)

整个项目是纯前端单体：Vue 3 + Vite + Pinia + vue-router + vue-i18n，31 个 SFC、约 1.5 万行，六个功能模块（爆款复刻、数字人像、文本生视频、音色更换、作品库、成本管理）。这篇文章不复盘业务，只复盘五个关键决策和踩过的坑——它们决定了这个工具是「能跑的 demo」还是「每天敢真金白银调用的生产线」。

## 一、整体架构：纯前端单体 + Node 代理网关

```
浏览器（Vue 3 SPA）
 ├─ 功能层：爆款复刻 / 数字人像 / 文本生视频 / 音色更换
 ├─ 资产层：IndexedDB（Blob）+ localStorage（元数据/缩略图）
 ├─ 状态层：Pinia stores（任务轮询 / 作品库 / 成本记账）
 │      │ /atlas-api、/ark-api、/atlas-dl
 │      ▼
 Node 代理层（Vite 服务端中间件，key 只在这一侧注入）
 │      ▼
 模型中转站（610 个模型目录：Video / Audio / Text 统一 OpenAI 风格接口）
```

**为什么不上后端？** 不是偷懒，是成本结构决定的。这个工具的所有服务端需求只有一个：转发模型调用。而模型调用是「浏览器发起 → 代理转发 → 拿结果回传」，没有业务状态、没有数据库、没有队列——单人维护的项目，为一条转发链路养一个后端服务，运维成本大于收益。

但纯前端有一个致命问题：**API key 放哪？** `VITE_` 前缀的变量会被 Vite 内联进 dist 产物，等于把 key 公开在 bundle 里。我的解法是把代理做进 Vite 的服务端中间件：浏览器只请求 `/atlas-api/*`、`/ark-api/*` 这些同源路径，Node 侧读 `.env.local` 注入 Bearer key 再转发上游。**key 永远不进前端产物**，开发体验上又和无后端完全一致。这个模式后来还兜住了第二个坑（见踩坑实录第 2 条）。

代价也说清楚：纯前端没有任务持久化，刷新页面进行中的任务状态会丢（我用 localStorage 快照缓解）；没有用户体系，成本数据只在本地。这些边界是主动选的，见第五节。

## 二、字幕绝不让模型烧——客户端后期字幕

这是整个项目我最得意的一个决策，它同时解决了质量、成本、迭代速度三个问题。

**背景**：视频生成模型往画面里渲染中文，效果不可靠——错字、模糊、片头还常被自由发挥出说明性文字。更麻烦的是字幕烧进画面后，改一句台词就要重跑一次生成模型：按 $0.015/秒的口播模型计价，每轮文案微调都是真金白银，迭代速度直接被模型排队时间锁死。

**方案是把字幕从生成链路里整个剥出来：**

1. **生成端禁烧字**。提示词硬约束「画面中不得出现任何文字、字幕、标题、贴纸」，保持画面纯净。有个细节：AI 拆解出的脚本里本来有一节【字幕样式】，这一节**下发生成模型前要删掉**——留着它会诱惑模型照着「烧字」。
2. **口播带时间轴**。口播文案强制按 `[起-止秒]台词` 格式逐句输出，前端解析成字幕 cues。用户手写台词没有时间码也不丢：顺接在前句之后按成片时长均分。
3. **播放时叠加真字幕**。监听 `timeupdate`，按当前时间命中 cue，DOM 层渲染——字幕永远清晰、逐字与文案一致。
4. **下载时客户端烧录**。canvas 逐帧画「视频帧 + 当前句字幕」，`MediaRecorder` 重编码导出（mime 优先 mp4、不支持兜底 webm，10 Mbps），字幕样式随分辨率缩放、单行超 14 字自动换行，与预览同一套排版规则。

烧录有三个工程细节值得一提：

- **音轨静音截流**：`createMediaElementSource` 把音轨截进 WebAudio 图谱，元素不再直连扬声器，只把流送进录制流——导出全程不外放声音，不干扰使用。
- **实时代价透明**：MediaRecorder 是实时重编码，耗时≈成片时长，导出前 toast 明确告知「约需成片时长，请勿切换页面」。
- **失败不阻断**：无解码环境或中途失败，自动退回原片直下，并 toast 说明——下载永远成功，只是可能没字幕。

结果：字幕这层彻底变成「文本编辑」，改文案零模型成本、秒级生效；成片视频从头到尾只生成一次。

## 三、AI 编导：多模态模型当编导，生成模型当摄影棚

爆款复刻的第一步是「拆解对标视频」：这条视频的场景、分镜、运镜、转场、音乐音效是什么，口播逐字说了什么。这步交给多模态文本模型（Gemini 4 Argon Developer，实测支持 `video_url` 内联视频输入），产出一份 450 字以内的「重拍脚本」+ 带 0.1 秒精度时间码的口播逐字转写。

**输入侧的降级链**值得展开，它决定了这条链路在各种浏览器环境下的存活率：

```
已裁剪片段 → MediaRecorder 真实裁出 webm（首选）
   ↓ 裁剪重录失败（无解码环境/不支持 MediaRecorder）
整段视频 ≤20MB → base64 内联 video_url
   ↓ 超限
canvas 抽帧 ×10 → image_url 多图降级
```

裁剪重录本身是个小工程：`canvas.captureStream(30)` 逐帧录制，音轨同样走 WebAudio 截流（分析过程全程静音）；统一压到 480p——场景/动作/字幕样式足够分析，payload 减半，长连接被掐的概率大幅下降。

**提示词约束是另一个隐形难点**：这条链路的语义是「达人和商品都将被替换」，所以提示词开头就锁死——不许描述达人样貌穿着、不许描述商品外观、原视频字幕一个字不许出现。没有这几条，拆解脚本会把你不需要的东西（原达人的形象、原商品的细节）写进重拍指令，生成端照着执行就全错了。

**输出解析做了三级兜底**：JSON 解析 → 按【口播文案】分隔符切 → 全文归分镜。模型输出永远是不可信输入，`finish_reason=length` 时明确报错而不是静默交出半份脚本。

## 四、生成任务的状态机：对「不可靠依赖」做容错

真实生成走「上传素材 → 提交任务 → 轮询状态 → 取结果」四步，全部经代理调用模型平台。10 秒的视频实测约 70 秒出片，这段窗口里的每一次轮询都可能遇到网络抖动。

轮询状态机有三个设计点：

**网络错误不是任务失败。** 单次空响应、5xx、429、网关返回 HTML 错误页，一律归入 `network-error` 容错态——连续 10 次（约 1 分钟）才判失败。这个分支是被真实事故逼出来的：曾经一次网关空响应把进行中的任务误判成失败，用户看着 90% 进度突然弹「生成失败」，而任务实际在远端跑完了。

**成功只是中转，不是终点。** 结果 URL 是对象存储签名链，24 小时失效。所以终态回调里第一件事就是把视频 fetch 回来转成 Blob 存进 IndexedDB（下载走 `/atlas-dl` 代理绕 CORS），作品库此后永远播放本地副本。

**store 层管理轮询生命周期。** 模块级 timer 句柄防重复 `setInterval`，无 pending 任务自动清 timer，页面卸载清理，连续异常计数熔断。失败的任务保留 `predictionId`，用户可以一键「按任务 ID 重查」复活——远端可能早就跑完了。

## 五、浏览器里的资产层：IndexedDB 双层结构

素材和作品的持久化用了一个双层结构：

- **Blob 原文件 → IndexedDB**（库名 `vs-assets`）：视频/图片/音频原文件；
- **元数据 → localStorage**：名称、类型、时长、320px 缩略图（视频取首帧 canvas 截帧），列表渲染永远不碰大对象。

还有一个容易被忽略的语义问题：**作品和素材是两个集合**。用户上传的原料是素材；生成的成片是作品（进作品库，带工具/模型/成本元数据），但它同时需要底层 Blob 才能播放。我用 `inLibrary` 标记区分——作品产物打上标记后在素材库、选择器等一切列表里隐藏，「项目是项目，素材库是素材库」，且任何写入路径都做幂等纠正。

工程底线：IndexedDB 不可用时静默降级（返回 null），上传主流程永远不被持久化故障阻塞。

## 六、把成本当一等公民：成本中心与记账口径

接了 610 个模型的目录后我发现，这类工具最容易死于一笔糊涂账：不知道哪次调用花了多少钱，不知道哪个模型在放血。所以成本中心从第一周就是功能模块，不是报表附件。

**记账口径按模型类型分三档**：视频/音频按次或按秒（数字人口播 $0.015/秒、爆款复刻 $0.109/次起）；文本按 token，输入输出分开计价（Gemini 分析通道 $1.2 in / $6 out 每百万 token，口播文案可切到 $0.0008/1M 的国产 Flash 档——同一件事的成本差两个数量级，这就是做模型路由的意义）。文本类记账不用估算，直接取响应里的真实 `usage` 乘单价。

**成本中心**本身有概览四卡（累计/本月/次数/均价）、每日成本柱状图（纯 SVG 手写，不引图表库）、工具×模型双维度聚合占比和分页明细。每次生成提交成功即记账，模型名、规格（分辨率·时长）、费用一条不落。

![成本管理中心](/uploads/2026-11/daren-cost.webp)

配套一条**成本铁律**：能本地做的不调 API。模型目录拉取走免费接口 + 24 小时缓存 + 内置离线兜底清单（断网也能选模型）；音色试听这类纯 UI 反馈一律本地合成；每一个真实调用都有账可查。

## 七、踩坑实录

**1. dataURL 的 MIME 参数带 codecs，中转站 400。** `MediaRecorder` 录出的 mimeType 是 `video/webm;codecs=vp9,opus`，转 dataURL 后这个带逗号的参数会把所有按逗号切 MIME 的代码搞坏（正确姿势是按 `;base64,` 定界）。更坑的是中转站某天起直接拒收带 codecs 参数的 data URL——裸 `video/webm` 正常。解法：转 dataURL 时只保留主类型。

**2. 系统代理掐大上传。** 浏览器直连中转站上传 20MB 级 base64，稳定 `ERR_CONNECTION_CLOSED`——curl 直连正常，只有浏览器被掐（系统代理对大 body 的处理问题）。解法：所有模型流量统一走本地 Node 代理，请求从 Node 直连上游，和 key 注入用了同一条路径。一次架构决策兜住两个坑，这是把代理层做进 Vite 中间件的最大回报。

**3. 思考型模型的 max_tokens 陷阱。** 推理 token 也算进 `max_tokens`，思考型模型思考完就把上限烧完了，正文一个字没写。解法：截断后上限翻倍重试一次；仍截断但内容已像完整产出（比如口播已带时间码）就收下，否则明确报错。

**4. 中转层偶发给模型注入工具。** 偶现 `finish_reason=tool_calls`、content 为空——中转层注入了它自己的工具定义。解法：检测到后追加一轮「此前误触发了工具调用，本次禁止」的多轮对话重试。

**5. 字幕诱因要连根拔。** 禁烧字提示词上线后仍偶发烧字，排查发现是分析脚本里的【字幕样式】小节原样下发——模型看到样式描述就手痒。解法：下发前把这一节从脚本里删掉。「提示词工程」不只是写指令，还要管理模型的注意力来源。

## 八、现状与下一步

现状：六个模块日常可用，真实生成链路（爆款复刻 / 数字人像 / 文本生视频）+ 真实 AI 编导（视频分析 / 口播文案）全部接通，成本记账逐条落账，平均单次生成 $0.087。

下一步按优先级：

1. **生成管线上独立后端**：任务持久化、断点续跑、多任务并发——纯前端方案的已知边界，也是它下一步要还的债；
2. **多模型并发比价**：同一 prompt 并发两个模型，先回的先用，顺手拿到 A/B 素材；
3. **模板库**：把高频的分镜结构沉淀成可复用模板，进一步压缩「拆解 → 生成」的链路。

一个人做工具的好处是决策不用开会：字幕客户端化、代理层兜 key、成本铁律，这三个决定让这个工具从「演示」走到了「日常敢用」。坏处是所有债也是自己背——所以每一步扩展前，先想清楚这笔账划不划算。
